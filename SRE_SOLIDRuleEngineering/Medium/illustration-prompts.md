# Medium illustration prompts

All five illustrations use the built-in image generation path and a shared visual system: 2:1 landscape, dark navy engineering blueprint, cyan/teal traceability, and amber/orange risk or uncertainty signals. No title text is embedded in the images.

## M_SRE_A_01

Show SOLID as an engineering response to software change, connecting requirement and use-case signals, object-oriented boundaries, architecture, iteration, and a maintainable modular system.

## M_SRE_A_02

Contrast abundant AI code throughput with scarce engineering judgment: a fast production engine floods several lanes with code modules, while a careful decision gate admits only verified modules into the stable architecture.

## M_SRE_A_03

Compare code inference with requirement-semantic inference. Two evidence lenses inspect the same system, while bidirectional traceability connects structural facts with actor goals, policy, constraints, and change drivers.

## M_SRE_A_04

Show ungrounded variability producing two extremes: false split creates excessive layers and interfaces; false cohesion compresses unrelated policies into a tangled monolith. A grounded requirement path supports the balanced alternative.

## M_SRE_A_05

Show that the difference between SOLID for Human and SOLID for AI is access to semantic context. Human organizational knowledge and an AI context window connect through a shared, persistent requirement-to-design traceability spine.
